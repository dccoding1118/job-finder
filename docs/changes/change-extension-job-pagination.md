# Extension 清單分頁與瀏覽連續性

## 背景／動機

Job API 預設每頁回傳 20 筆，但 Side Panel 只讀取第一頁，超過 20 筆的推薦或篩選結果無法由日常操作介面查看。API 設計雖已宣告 `cursor`，handler 尚未產生或接受下一頁 cursor。

## 決策摘要

- Job、待看與 Run 清單使用不透明 cursor 分頁；每頁預設 20 筆，合法範圍為 1–100 筆。
- Side Panel 的推薦頁與待看頁在尚有下一頁時顯示「載入更多」，由明確使用者動作追加後續 Job，不覆蓋已載入項目。
- Side Panel 在頁面生命週期內分別保存四個頁籤的捲動位置；從推薦清單開啟職缺再返回時，回到原清單位置。
- 推薦清單在頁面生命週期內將已開啟的職缺標示為「已看」，不寫入 extension storage。
- 變更篩選或按重新整理會回到第一頁；分頁請求期間停用載入按鈕，過期回應不得寫回新篩選結果。
- Run 歷程仍只顯示第一頁；本變更不擴張其介面操作範圍。

## 相對舊狀態的差異

| 主題 | 舊狀態 | 最新狀態 |
|---|---|---|
| API cursor | 永遠回 `null`，傳入 cursor 不生效 | 驗證 cursor、依位置取頁並回下一頁 cursor |
| 推薦與待看清單 | 只顯示第一頁 20 筆 | 可逐頁追加直到沒有下一頁 |
| 頁籤切換 | 每次切換回頁面頂端 | 各頁籤恢復離開前的捲動位置 |
| 職缺瀏覽狀態 | 清單無法辨識當次已開啟項目 | 當次頁面以「已看」樣式區分 |
| 篩選切換 | 重新取得第一頁 | 重新取得第一頁並清除舊 cursor |
| 非法分頁參數 | 非法 limit 可能回空清單 | 非法 limit 或 cursor 回 400 |

## 已知殘留限制

- cursor 表示目前排序結果中的位置；分頁期間若評分或職缺更新導致排序改變，重新整理會以最新排序從第一頁載入。
- Run 歷程頁尚未提供載入更多控制項。
- 頁籤捲動位置與已看標記只存在當次 Side Panel 頁面記憶體；關閉或重新載入後重設。
