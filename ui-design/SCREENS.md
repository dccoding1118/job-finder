# jobfinder Side Panel screens

## 產品介面模型

Chrome 原生 Side Panel 是 extension 的主要操作面。支援網站的 content script 負責讀取使用者已載入的頁面、正規化職缺資料並在列表項目顯示小型判定標記；Side Panel 不直接依賴來源網站 DOM。

Panel 的主要頁籤固定為「目前職缺、待看、推薦、系統」。來源擴充只增加 capture adapter 與來源標籤，不增加來源專屬主畫面。

## 共用 Header

| 區域 | 內容 | 行為 |
|---|---|---|
| 品牌列 | jobfinder、API 連線狀態、主題、重新整理 | 切換淺色／深色主題；重新取得目前分頁與 API 資料 |
| 頁面脈絡 | 來源、目前職稱摘要、擷取狀態 | 無支援頁面時顯示中性說明 |
| 頁籤 | 目前職缺、待看、推薦、系統 | 保留目前頁籤選擇；數量即時更新 |

## 目前職缺

內容優先序：判定 → 總分／命中條件 → 推薦理由 → 五維評分 → 職缺摘要 → 求職信／下一步。

| 狀態 | 主內容 | 主要動作 |
|---|---|---|
| `recommended` | 推薦、總分、五維、理由 | 產生求職信 |
| `not_recommended` | 不推薦、總分、五維、理由 | 開下一筆 |
| `unfit` | 不適合、命中條件 | 開下一筆 |
| `pending_detail` | 待補全文、目前已知欄位 | 在目前分頁取得完整內容 |
| `pending_score` | 評分中、已完成的條件篩選 | 保持 Panel 開啟等待結果 |
| `budget_exhausted` | 今日評分額度已用盡 | 保留職缺至隔日 |
| 無支援頁面 | 說明此分頁不支援擷取 | 切換至待看或推薦 |

求職信狀態：

| 狀態 | 呈現 |
|---|---|
| `none` | 說明按需生成與「產生求職信」 |
| `requested` | 處理中、停用重複要求 |
| `ready` | 經審查信件、複製、投遞狀態 |
| `failed` | 未過審說明與「再次產生」 |
| `unavailable` | 非推薦職缺不顯示生成入口 |

## 待看

顯示 `discovered` 職缺。每列包含職稱、匿名公司類型、來源、地點與已知薪資；點擊後由使用者在原網站開啟職缺，不由 extension 背景開頁。

頂部說明待看清單的目的，並提供巡邏動線的進度。空狀態說明目前沒有需要補全文的職缺。

## 推薦

顯示所有推薦職缺，依總分由高到低排列。每列包含總分、職稱、匿名公司類型、來源、求職信狀態與投遞狀態。

點擊職缺後切換到「目前職缺」呈現完整對照。這個切換不代表瀏覽器自動打開來源頁面；原始連結是明確的使用者動作。

## 系統

| 區塊 | 內容 |
|---|---|
| 連線 | localhost API、常駐 worker、每日自動抓取時間 |
| 抓取 | 顯示 systemd 背景排程的台北時間；手動觸發全自動來源抓取，不觸發支援網站背景開頁 |
| 最近執行 | 開始時間、trigger、抓取事實、錯誤摘要 |
| Prototype 狀態 | 僅設計稿可用，切換推薦、評分中、不適合、信件就緒、API 離線 |

## 回饋與失敗

- Loading 使用局部 skeleton，不清空已存在內容。
- API 離線顯示固定 callout，停用需要寫入的操作，保留最近一次內容。
- Token 無效說明前往 extension Options 處理，不在 Panel 顯示 token。
- 擷取失敗提供使用者觸發的重試，不做背景高頻重送。
- Copy 成功以 toast 回饋；失敗時信件仍可選取並顯示手動複製說明。
- 所有非同步按鈕送出後立即進入 busy 狀態並避免重複觸發。

## 響應式與無障礙

- 320px 以上維持單欄可用；寬度增加時只放寬文字與卡片，不切成桌面多欄。
- Header 與 action bar 可固定；內容本身保持單一垂直捲動區。
- Page tabs 使用 `tablist`／`tab` 語意，畫面使用 `tabpanel`。
- Focus ring 清楚可見，鍵盤順序依畫面閱讀順序。
- 判定與狀態均包含文字；進度條提供可讀數值。
- 動畫遵守 `prefers-reduced-motion`。
- 淺色與深色主題的功能、狀態文案與鍵盤順序完全一致。
